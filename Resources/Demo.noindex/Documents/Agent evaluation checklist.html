Agent evaluation checklist

Run through this before every release of the support agent, and again whenever the model, the instructions, a tool or the policy documents change. A release ships only when every box in the first five sections is ticked.

1 · Define the job

  • Write down what the agent does: order status, returns and replacements, product questions.And what it never does: refunds above €500, changes to addresses, medical or legal advice.
  • Agree on success criteria with the support leads.For example: resolves at least 60% of return requests without a person, with no wrong policy answers.
  • Name an owner for the agent and an on-call contact for incidents.

2 · Build the test set

  • At least 100 real conversations, anonymized, with the expected outcome for each.
  • Edge cases: orders older than a year, damaged items, partial deliveries, two orders in one message.
  • Questions outside its job, which it should decline politely or hand to a person.
  • Adversarial inputs: jailbreak attempts, and instructions hidden in an order note or a document (indirect prompt injection).
  • Both languages we support: English and Spanish.

3 · Measure quality

  • Run the built-in evaluators on the whole test set.Intent resolution, tool call accuracy, task adherence, groundedness and relevance (see src/evaluate.py).
  • Check every answer that cites a policy against the current PDF, page by page.
  • Compare with the previous version: no metric may drop by more than 5%.

4 · Safety

  • Guardrails on for prompts, outputs, tool calls and tool responses.
  • Run the AI red teaming scan and fix what it finds.
  • No personal data in logs or traces beyond the order number.

5 · Tools

  • Each tool can do only what it needs to (least privilege).lookup_order is read-only; create_return can't refund, only open a return.
  • The agent asks before any action the customer can't undo.
  • Tools time out after 10 seconds and the agent says so instead of guessing.

6 · People

  • Support leads review 50 conversations from the test run.
  • Handing over to a person works, with the whole conversation attached.

7 · After release

  • Tracing on for every conversation.
  • Continuous evaluation on a sample of live traffic, with an alert when a metric drops.
  • Thumbs up and down in the chat, reviewed every Friday.
Based on the evaluation, tracing and guardrail features described in What is Microsoft Foundry? Contoso Outdoor is a fictitious company used for demos.
